# 第 1 步已接受的规格修订

这些规则用于第 02–04、06–10 题。对应题目写进 `tasks/` 之前，先按这里改需求。第 05 题已按冻结稿写在 `05.md`。

预定调试组：04、05、08。其余留到最后评测。不另设公开用例和隐藏用例。

## 通用约定

- 检查顺序：参数个数，非文件参数的格式，文件名是否含 `/` 或 `\`，文件是否存在，文件内容。
- 文件名含目录分隔符时，按文件不存在处理。
- 按行读取时，文件末尾的一个换行不算空行。输入行允许 LF 或 CRLF。输出换行固定为 LF。

## 分题

- 02：成绩和 `minimum_score` 使用规范十进制，不接受正号和前导零。CSV 只在字段含逗号、双引号或换行时加引号。
- 03、09：要求整数的 JSON 字段，只接受不带小数点、不带指数的 JSON 整数。`25.0`、`2e1` 都非法。布尔值不能当整数。
- 04：每一行各计一次，重复文件名不合并。最后一个点后面是空串时，扩展名为 `(none)`。
- 06：日期、时间、级别、消息之间恰好各一个 ASCII 空格。消息内部可以有多个空格，至少有一个非空白字符，不能另起一行。
- 07：空行报错，不跳过。嵌套对象的键顺序保持输入顺序。`value` 仍允许任意合法 JSON，包括小数和科学计数法。
- 08：数量不接受前导零和 `-0`。输出用规范十进制。
- 10：不做 `%` 插值。去掉行首空白后，以 `#` 或 `;` 开头的整行是注释。section 名去掉首尾空白，空名非法。没有键的 section 不输出。同一文件里 section 重复要报错；两个文件里出现同一个 section 是合法合并。无法识别的行报错。
