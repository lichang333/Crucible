# 任务 06：日志级别统计

- 状态：手写通过
- 分组：留考
- 入口：`python3 tool.py <application.log>`

规格已核对，手写参考实现通过本题全部验收用例。改需求或验收前先改状态。

## 需求

编写 `tool.py`，统计日志里五种级别出现的次数。程序只接收一个命令行参数：

```text
python3 tool.py application.log
```

规则：

1. 参数必须恰好是一个文件名，不能含 `/` 或 `\`。检查顺序：参数个数，文件名里有没有目录分隔符，文件是否存在，文件内容。
2. 文件是 UTF-8 文本。行分隔只认 LF 和 CRLF。读入时去掉这一处行分隔。文件末尾的一个行分隔不再多出一行。最后一行可以没有行分隔。空行非法。
3. 每一行必须是：`YYYY-MM-DD`、一个 ASCII 空格、`HH:MM:SS`、一个 ASCII 空格、级别、一个 ASCII 空格、消息。这三处分隔都必须恰好是一个空格。
4. 日期必须完全匹配 `YYYY-MM-DD`，并且是真实公历。规则与第 05 题相同。`2024-02-29` 和 `2000-02-29` 合法，`1900-02-29`、`2025-02-29`、`2026-1-17` 非法。
5. 时间必须完全匹配 `HH:MM:SS`。时是 00 到 23，分和秒是 00 到 59。`60` 秒非法。
6. 级别只能是 `DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL`。
7. 消息可以以空格开头并包含多个空格；“空白字符”按 Python 3 `str.isspace()` 判断。消息至少要有一个不被 `str.isspace()` 判为空白的字符，不能另含 CR 或 LF。级别后的第一个空格是字段分隔符；其后的空格属于消息。
8. 只统计级别字段，不统计消息正文里出现的级别单词。
9. 五种级别都要输出，没有出现的级别计数为 0。顺序固定为 `DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL`。格式是 `级别 次数`，中间一个 ASCII 空格。
10. 零字节文件合法，五种级别都输出 0。每行以 LF 结束，最后一行也有 LF。成功时标准错误为空，退出码 0。

出错时标准输出为 0 字节，标准错误恰好是下面某一行加一个 LF，退出码 2。

- 参数个数不是一个：`ERROR: usage: tool.py application.log`
- 文件名含 `/` 或 `\`，或文件不存在：`ERROR: input file not found`
- 编码、空行、日期、时间、级别或消息不合法：`ERROR: invalid log file`

## 验收

只给评测用。每个用例单独在空目录里运行。成功时标准输出都是五行，顺序不变。

### 用例 1：五种级别

准备 `application.log`，末尾有 LF：

```text
2026-11-17 09:00:00 INFO Application started
2026-11-17 09:01:00 DEBUG Loading configuration
2026-11-17 09:02:00 WARNING Disk usage high
2026-11-17 09:03:00 ERROR Connection failed
2026-11-17 09:04:00 INFO Retry started
2026-11-17 09:05:00 CRITICAL Service unavailable
```

命令：

```text
python3 tool.py application.log
```

期望：

- 退出码：0
- 标准输出：`DEBUG 1`、`INFO 2`、`WARNING 1`、`ERROR 1`、`CRITICAL 1`，每行加 LF
- 标准错误：空
