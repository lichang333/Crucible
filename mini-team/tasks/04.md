# 任务 04：文件扩展名统计

- 状态：手写通过
- 分组：调试
- 入口：`python3 tool.py <filenames.txt>`

规格已核对，手写参考实现通过本题全部验收用例。改需求或验收前先改状态。

## 需求

编写 `tool.py`，统计一个文件名清单里的扩展名。程序只接收一个命令行参数：

```text
python3 tool.py filenames.txt
```

程序只读这个清单，不访问、不创建清单里写出的那些路径，也不修改清单文件。

规则：

1. 参数必须恰好是一个文件名，不能含 `/` 或 `\`。检查顺序：参数个数，参数里有没有目录分隔符，文件是否存在，文件内容。
2. 清单是 UTF-8 文本。行分隔只认 LF 和 CRLF。读入时去掉这一处行分隔，不把 CR 留在文件名里。文件末尾的一个行分隔不再多出一行。最后一行可以没有行分隔。
3. 不去除文件名首尾空白。只含空格的行是文件名，不是空行。空行、空文件名、文件名含 `/` 或 `\`，都是清单错误。
4. 扩展名是最后一个 `.` 之后的部分，再用 Python 的 `str.lower()` 转换，不用 `casefold`。
5. 没有 `.`，或者最后一个 `.` 在首字符，或者最后一个 `.` 后面是空串时，扩展名记为 `(none)`。因此 `README`、`.config`、`file.`、`..` 都是 `(none)`。`archive.TAR.GZ` 的扩展名是 `gz`。
6. 每一行各计一次。同名文件出现几次就计几次。
7. 按扩展名字符串的 Unicode 码点升序输出，不按数量排序。`(none)` 的首字符是 U+0028，排在英文字母之前。
8. 每行格式是 `扩展名 数量`：中间恰好一个 ASCII 空格，数量是不含正号和前导零的十进制整数。不输出表头。
9. 零字节清单合法，标准输出为 0 字节，退出码 0。有结果时，最后一条结果行后面恰好一个 LF。成功时标准错误为空。
10. 标准输出和标准错误都使用 UTF-8，换行只用 LF。

出错时标准输出为 0 字节，标准错误恰好是下面某一行加一个 LF，退出码 2。

- 参数个数不是一个：`ERROR: usage: tool.py filenames.txt`
- 参数含 `/` 或 `\`，或文件不存在：`ERROR: input file not found`
- 清单不是合法 UTF-8，或含空行、空文件名、带目录分隔符的文件名：`ERROR: invalid filename list`

## 验收

只给评测用。每个用例单独在空目录里运行。下面用「加 LF」表示该行以一个 LF 结束。失败时标准输出是 0 字节，不是只有换行的空行。

### 用例 1：普通扩展名

准备 `filenames.txt`，末尾有 LF：

```text
report.pdf
photo.jpg
data.csv
backup.pdf
```

命令：

```text
python3 tool.py filenames.txt
```

期望：

- 退出码：0
- 标准输出：`csv 1` 加 LF，`jpg 1` 加 LF，`pdf 2` 加 LF
- 标准错误：空

排序理由：`c`（U+0063）在 `j`（U+006A）之前，`j` 在 `p`（U+0070）之前。

### 用例 2：大小写、多个句点和 (none)

准备 `filenames.txt`，末尾有 LF：

```text
archive.TAR.GZ
photo.JPG
report.tar.gz
README
.config
```

命令：

```text
python3 tool.py filenames.txt
```

期望：

- 退出码：0
- 标准输出：`(none) 2` 加 LF，`gz 2` 加 LF，`jpg 1` 加 LF
- 标准错误：空

`README` 和 `.config` 都是 `(none)`。两个 `gz` 来自 `archive.TAR.GZ` 和 `report.tar.gz`。`(none)` 排在 `gz` 前面，因为 U+0028 小于 U+0067。
